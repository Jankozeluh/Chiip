# Chiip — instructions for Claude

Chiip is a single-player, CS-style tactical FPS against bots with a retro Quake look, built in Godot 4.7.2 with GDScript. Read README.md first. The roadmap and current status are in docs/PLAN.md.

## The user

- A data analyst who has made games in Unity before but is new to Godot.
- Wants to learn as we go. Briefly explain each Godot concept the first time it's used, comparing it to Unity. Skip programming basics.
- A long-time CS and Quake player. Use CS terms freely (counter-strafe, spray, eco), and aim for a CS-like feel.

## Documentation rules (required)

Everything must be documented, in the same change as the work itself, not later:

1. **docs/PLAN.md:** tick finished tasks and update the milestone status and "Current milestone".
2. **docs/DEVLOG.md:** add or extend today's entry with what was done and what's next.
3. **docs/DECISIONS.md:** add an entry for every design or technical decision, with the reasons and the alternatives. Move resolved open questions into entries.
4. **docs/ARCHITECTURE.md:** update when adding folders, systems, autoloads, physics layers or conventions.
5. **docs/LEARNING.md:** add a note when a Godot concept is used for the first time, with the Unity comparison.
6. **docs/GAME_DESIGN.md:** update when gameplay rules or values change.
7. **README.md:** update when how to run the game, or its controls, change.
8. **Code:** every script starts with a `##` doc comment. Exported variables and public functions have `##` comments.

Update the "Last updated" date on every document you change.

## Workflow

- Work milestone by milestone and task by task, following docs/PLAN.md. Ask the user before starting a new milestone or changing the plan.
- The game must still run after every task.
- Once git is set up in M1, commit after each finished task, with the message prefixed by the milestone, e.g. `M1: Add crouching`.
- Use third-party assets only if their license allows it, and record each one in docs/CREDITS.md. Ask the user before every download (file, source, size). Downloads go to the scratchpad, each in its own folder; only processed results go into the project.

- **Watch the usage limit** (the user's request, 2026-10-16: "davej pozor na ty limity a pouzivej agenty respektive modely efektivne"):
  - One subagent at a time, with a tight brief; no parallel fan-out.
  - Run only the suites a change touches (`bash tools/run_tests.sh <names>`); do the full run once, at the end of a milestone or before a merge.
  - Read only the parts of files you need (grep, line ranges).
  - One screenshot comparison per screen, read at a reduced scale.
  - Keep reports short.

## Gotchas

- In hand-written `.tscn` files, a node that sets an exported *node* variable needs `node_paths=PackedStringArray("var_name")` in its `[node]` header, or the reference silently stays null.
- Input bindings created from code need `device = -1` (all devices), like bindings made in the editor.
- In a `--script` that extends `SceneTree`, nodes added in `_init()` aren't ready yet, so `@onready` variables are null. Await a few `physics_frame`s first.
- TrenchBroom maps are built with Chiip's worldspawn class (`maps/fgd/`, set in `maps/chiip_map_settings.tres`), which stores each face's texture for footstep and impact sounds (`Surfaces`). Keep it when changing map settings, or every floor sounds like concrete.
- A built TrenchBroom map scene stores references to its textures. Rebuild the map (tools/build_maps.gd) *before* deleting or renaming a texture it uses, or the scene can't be loaded anymore.
- Multiplayer comes in M9 (D-033). Follow "Keeping multiplayer possible" in docs/ARCHITECTURE.md in all gameplay code.
- Export a build (`--export-release`) only when the user asks for one.
- Keep Chiip visually distinct from Counter-Strike: no desert/dust palettes, no CS-like map layouts or names (D-031).
- Headless runs use a dummy audio driver where sounds never finish; anything still "playing" at exit is reported as leaked. Tests use silent weapon data.
- In an exported game scenes are stored converted (`depot.tscn` becomes `depot.tscn.remap`): list resources with `ResourceLoader.list_directory()`, not `DirAccess`, and load them by their `.tscn` path as usual.
- Autoloads don't exist in `--script` runs (tools, checks), so code that tools load must not use autoload names. Use a class with a static shared instance instead (see `systems/noises.gd`).
- GDScript lambdas copy captured locals: assigning to a captured `int`/`Vector2` inside a lambda doesn't change the outer variable. Capture an `Array`/`Dictionary` instead.
- `Teams` and `Character` refer to each other. In such a cycle GDScript can reject an enum from one of them passed in from a third script ("should be Side but is Teams.Side"). Take such parameters as `int`.
- Practice mode is the main menu's Practice button, or `-- --practice`: the Shooting Range (`Settings.DEFAULT_MAP`, D-141; a match starts on `Settings.DEFAULT_MATCH_MAP`, Depot), with no bots until the console adds them (`practice_bots` metadata on the map's root); with `--map` it is practice on that map with two bots. The test map is hidden from the player (`GameLaunch.HIDDEN_MAPS`) but stays the tests' map and main.gd's fallback; `-- --match` starts the default 3v3 match (bomb rounds on maps with bomb sites), `-- --respawn` the team respawn mode. These command-line flags skip the menu and ignore the saved match setup; in the menu, the Play screen's cards play the Custom choices in that mode (D-135). A plain run shows the menu, so smoke runs of the game use a flag.
- Jolt moves a teleported body (`global_position = …`) only at the next physics step; other bodies moving in the same tick still collide with its old position. `Character.respawn()` handles this by skipping movement for that tick.
- Headless runs can't capture the mouse: `Input.mouse_mode` always reads visible, so `PlayerController` treats every click as the click that recaptures the mouse. Test click handling in a windowed run, or call the public method behind it (e.g. `spectate_next()`).
- The navigation map picks up a newly added map's navmesh a few physics frames later; queries before that answer for the previous map or the origin. Wait as `tests/maps_test.gd` does (`_wait_for_navigation()`).
- Map rules for the quick maps (look: at most 5 materials, no saturated red or blue on large surfaces, neutral shadows; building: no steps, gap widths, cover heights; marker groups) are in docs/MAPS.md. After changing a map's layout: build, bake, then run the maps test and `tools/map_report.gd`.
- HUD and overlay `Control`s must have `mouse_filter = IGNORE` (Label's default; containers and panels default to STOP), or they swallow the clicks `PlayerController` needs. Menus that should block clicks use a full-screen STOP background.
- A parse error in a test script makes the suite exit with code 0 and print no PASS lines, which looks like a pass. When running suites, check the PASS count and grep for `SCRIPT ERROR`, not only the exit code. `tools/run_tests.sh` does both.
- `Character.weapon` is the weapon *in hand* and changes with every switch (M7, D-094). Code that listens to a weapon's signals must follow `Character.weapon_changed` and reconnect (the HUD, `CrewBody` and `BotController` do). Tests that need silence set the static `Weapon.silent = true` (every weapon a loadout creates has real sounds).
- Bots shop at every freeze time (`MatchSettings.bots_buy`, D-099), so bot armor and guns vary: a test that checks exact damage or money numbers with bots turns it off.
- In `.tres` and `.tscn` text, `Transform3D(...)` lists its basis **row by row**, not as the x, y, z axis columns: writing a rotation as columns gives the inverse rotation (M7's knife blade pointed down). Build it in code or read it back (`basis * Vector3(...)`) to check.
- Smoke clouds register in the static `Smokes` list (like `Noises`), which outlives a scene: a test that throws smokes calls `Smokes.clear()` when it starts over.
- Every menu registers with `MenuState.open(self)` / `close(self)` (ui/menu_state.gd). That's what stops gameplay input, shows the mouse, recaptures it when the last menu closes, and decides which menu Esc belongs to.
- `Window.content_scale_stretch = INTEGER` rounds the scale factor down: ask for the window size divided by a whole number, never an exact line count (`PixelView.get_pixel_scale()`).
- A script error inside a headless run can leave Godot running forever. Always pass `--quit-after <frames>` as a safety net (macOS has no `timeout` command).
- A `transition_request` on an `AnimationNodeTransition` is applied only when that node runs: one inside a OneShot's input (the crew graph's FireKind, AttackKind, ReloadKind) switches when the shot plays, so read its `current_state` after firing, not before.
- A new `AnimationNodeTransition` has no current state and outputs nothing (the model stays in its rest pose) until it gets a `transition_request`; `CrewBody` requests "alive" when it builds the tree.
- Menus take their look from the UI theme (D-057): pick *type variations* (list in docs/ARCHITECTURE.md, "The UI theme") instead of overriding colors, fonts or styleboxes on nodes, and scale a menu with `UiTheme.apply(self, factor)` in its `set_ui_scale()` (the HUD uses `UiScale`). `ui/chiip_theme.tres` is generated by `tools/make_ui_theme.gd`: change the tool, not the file. Every value is a token in `tools/ui_palette.gd` (D-131); the tool itself may not contain numbers (`ui_test` reads its source). Icons for weapons, gear, classes, headshot and health come from `UiIcons.get_icon()` (null while the slot is empty: show text then).
- Tests must never read or write the player's real settings file (`user://settings.cfg`). The shared `Settings.get_instance()` only saves after something calls `load_from_disk()` (the main menu does at a normal start and `main.gd` when started directly, unless its `load_settings` export is off or `Settings.is_loaded()` already), so a test that loads `main.tscn` sets `load_settings = false`, and a test of saving uses a separate `Settings.new()` with a temp path such as `user://test_settings.cfg`, deleted afterwards. `settings_test` checks the real file's checksum before and after.
- A settings change reaches the engine only through the shared instance (`applies_to_engine`); `Settings.new()` just holds values, so a test can't mute the audio or rebind keys by accident.
- A headless run's window is 64 × 64 and snaps back to that every frame. To test code that depends on the window size (`main.apply_pixel_settings()`), set `get_tree().root.size` and check the result in the same frame, without an `await` in between.
- `ConfigFile.get_value(section, key)` without a default is an error when the key is missing, and a default of `null` counts as none: use `has_section_key()` first.
- The audio buses are Master, Effects and Interface (`default_bus_layout.tres`, D-058). Put a new game sound on Effects (`bus = &"Effects"`), menu sounds on Interface, and never save the layout with a muted or turned-down bus (the editor's Audio panel writes that file).
- The pause menu (Esc, the `pause` action) pauses the whole tree (D-065). A paused node's `_process`, `_physics_process`, `_input`, timers and tweens stop, so anything that must keep working while paused has `process_mode = Always` in its scene: the pause menu, the settings menu, the console and the Tab scoreboard (it has to run to hide itself). A new menu, or a sound that must play while paused (a menu click), needs it too; a `create_timer()` in game code must pass `process_always = false` (`create_timer(time, false)`) or it keeps counting; anything that must stand still while paused must count time in `_physics_process` / `_process` deltas, never `Time.get_ticks_*`. Changing scenes while paused leaves the next scene paused: `Main.return_to_menu()` unpauses first. Tests that open the pause menu must unpause (`get_tree().paused = false`) in their cleanup. `AudioStreamPlayer.stream_paused` only changes for a player that is playing when the tree pauses.
- Online (M9) code never looks the session up globally: two games run in one test process (`tests/net_harness.gd`, each side with its own `SceneMultiplayer` and physics world). Use `Character.all_in_world(node)` / `Bomb.find_in_world(node)` instead of `get_nodes_in_group("characters")` / `"bomb"`, and let go of a `NetSession` when it emits `closed` (freeing it while a game still read it crashed the engine). `ui_test` prints one expected "Couldn't create an ENet host." line (its port-in-use check). The client predicts with exactly what it sends: angles go through `NetProtocol.quantize()` (32-bit floats) before the client simulates them.
- The map kit's props, lamps and their entity file are generated (`modelgen.py props`), and so are the kit gallery's `.map` (`tools/make_kit_gallery.py`) and every map texture (`tools/make_world_textures.py`): change the part lists or the tools, not the outputs. The three quick maps were dressed by editing their `.map` files (D-128), which stay the source.
- `tools/run_tests.sh` keeps each suite's log in `$TMPDIR/chiip-tests/`, which every session on this Mac shares: when other sessions run tests at the same time, run it as `TMPDIR=<your scratchpad>/tmp bash tools/run_tests.sh`, or the table can count another branch's lines.
- Godot imports every image in the project, also in `docs/`. A docs folder with pictures needs an empty `.gdignore` (as in `docs/maps/` and `docs/mapping/`).
